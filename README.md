# E4B Invoice to JSON — Fine-Tuning Worksheet

Teach a small open LLM (Gemma E4B) to turn messy invoice text — emails, one-liners, tables, WhatsApp Hinglish — into strict 8-field JSON. The exact core of a real SAP Accounts-Payable automation bot. Built as a beginner teaching track.

## Results (real run, free Kaggle T4 GPU)

| Metric | Base model (zero-shot) | Fine-tuned (80 examples, ~3 min) |
|---|---|---|
| Valid JSON | 55% | **100%** |
| All 8 fields exact | 0% | **85%** |
| Avg per-field accuracy | 10.6% | **97.5%** |
| Invented PO numbers | 0 | 0 |

3 minutes of QLoRA training (15 optimizer steps) on 80 synthetic examples moved perfect extraction from **0/20 to 17/20** held-out test cases. Loss: 0.475 to 0.053 to 0.022 across the 3 epochs.

## Quickstart

1. Open **worksheet/E4B_Invoice_Finetuning_Worksheet.ipynb** in Google Colab (or Kaggle)
2. Runtime, Change runtime type, T4 GPU
3. Run the cells top to bottom — about 30-40 minutes. The dataset is generated by code (seed 42), so no downloads and no API keys.

## How this was made

- **Dataset:** 100 handwritten-quality cases generated by a seed-42 script — the dataset is code, fully reproducible (data/make_invoice_dataset.py). 4 input formats, 3 deliberate edge cases (missing PO, GST-inclusive-only totals, missing payment terms).
- **Baseline:** zero-shot Gemma E4B (Q4_K_M) via llama.cpp on a CPU server, temperature 0.
- **Training:** QLoRA (r=16, alpha=16) with unsloth on a Kaggle T4 — training/train_reference_kaggle.py.
- **Eval:** identical harness on both sides — JSON validity, 8-field exact match, invented-PO counter. Loss is reported but never used as the quality metric.
